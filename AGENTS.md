# AI Agent Instructions for `voynich-attack` in Conscious-Relativity

This document provides instructions for AI agents (like GitHub Copilot) on how to correctly use the `voynich-attack` submodule within the context of the main **Conscious-Relativity** project.

## 1. Project Overview

This `voynich-attack` repository is used as a **submodule** for the parent project, "Conscious-Relativity" (https://github.com/wjbaker2025/Conscious-Relativity.git). Its primary purpose is to perform statistical text analysis on the Hebrew Tanach (Old Testament).

**The ultimate goal is to identify thematically relevant Hebrew words to populate the Gematria libraries required for the Ruach Equations in the parent project.** The statistical analysis performed here is a means to that end.

## 2. The Workflow: From Source to Analysis

It is critical to understand that this submodule does **not** operate independently. The entire workflow is orchestrated by scripts and data from the parent `Conscious-Relativity` repository.

### Step 1: Corpus Generation (Parent Project)
- The text files used for analysis are **generated** by the parent project.
- The authoritative script for this is `scripts/export_corpus.py` in the **root of the Conscious-Relativity project**.
- This script reads the source JSON files from `the_hebrew_holy_bible-tanach/` and creates individual `.txt` files for each book of the Tanach.

### Step 2: Corpus Location (This Submodule)
- The generated `.txt` files are placed into the `vendor/voynich-attack/corpora/hebrew/` directory.
- **CRITICAL**: Do not assume these files are static. They are generated by the parent project and can be updated at any time.

### Step 3: Analysis Execution (Parent Project)
- The analysis is **not** run using the example scripts included in this submodule (e.g., `examples/`).
- The analysis is initiated and controlled by custom scripts in the parent project, primarily `scripts/run_voynich_analysis.py` or similar. These scripts are designed to loop through the generated corpus files and produce structured reports.

### Step 4: Gematria Integration (Parent Project)
- The final output of the analysis (e.g., word frequency lists) is used to inform the selection of words for the Gematria libraries (e.g., `A_library.json`, `k_library.json`).
- The core thematic guidance for word selection comes from `docs/Thematic-Gematria Lexicon.md` and `AGENTS.md` in the parent project. The statistical analysis helps to find and prioritize candidate words from the source text.

## 3. Key Files and Directories

- **`Conscious-Relativity/` (Parent Project Root)**
  - **`scripts/export_corpus.py`**: **Source of truth** for creating the corpus files.
  - **`scripts/run_voynich_analysis.py`**: **Source of truth** for running the analysis.
  - **`the_hebrew_holy_bible-tanach/`**: The raw JSON data for the Hebrew Bible.
  - **`gematria_libraries/`**: The target JSON libraries that this analysis helps to populate.
  - **`AGENTS.md`**: The primary guide for the thematic meaning of each Gematria library.

- **`vendor/voynich-attack/` (This Submodule)**
  - **`corpora/hebrew/`**: The **destination** for all `.txt` corpus files. This is the data your analysis tools will read.
  - **`voynpy/reftext.py`**: This file has been **patched** to use `encoding='utf-8'` when opening files to handle the Hebrew text correctly. Do not change this unless necessary.
  - **`requirements.txt`**: This has been modified to resolve dependency conflicts.

## 4. Instructions for AI Agents

- **DO** use the scripts in the parent `Conscious-Relativity/scripts/` directory to run the export and analysis workflow.
- **DO** refer to the parent project's `AGENTS.md` and `docs/Thematic-Gematria Lexicon.md` to understand the purpose of the analysis.
- **DO** expect the corpus files to be located in `vendor/voynich-attack/corpora/hebrew/`.

- **DO NOT** run the scripts in the `examples/` directory of this submodule. They are not configured for the project's data or workflow.
- **DO NOT** modify the corpus files in `corpora/hebrew/` directly. They should be regenerated by running `scripts/export_corpus.py` from the parent project.
- **DO NOT** assume this submodule is a standalone project. Always operate within the context of the `Conscious-Relativity` parent project.
